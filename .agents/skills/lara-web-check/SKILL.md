# Lara 화면 검증

[로컬 개발](../../../docs/operations/local-development.md)의 실제 기록 재생 절차를 기본으로 사용한다. 사용 가능한 기록은 [fixture 안내](../../../fixtures/nexon/README.md)에서 확인한다. 같은 체크아웃의 기존 Nuxt 서버를 확인해 충돌을 피한다. 서버 코드를 별도로 복제하거나 브라우저 내부 상태에 가짜 결과를 주입하지 않는다.

변경한 기능의 계약을 [문서 안내](../../../docs/README.md)에서 확인한 뒤 해당 흐름만 검증한다. 군장검사는 [기능 문서](../../../docs/specifications/party-inspection.md)의 범위를 따른다.

- 군장검사는 기록된 여섯 이름으로 정상 자료와 `믹끼유`의 ID 조회 실패가 구분되는지 확인한다. 실제 이미지·장비 옵션·빈 슬롯을 포함해 변경한 영역을 살핀다.
- 실제 기록으로 재현하기 어려운 스탯 누락 등은 합성 미리보기의 `데모부분`이나 테스트 내 입력 변형으로 보완한다. 없는 스탯이 0이나 미착용 판정으로 바뀌지 않아야 하며, 기록한 원문은 수정하지 않는다.
- 수집 UI를 바꿨다면 갱신 중 기존 결과 유지, 완료·실패 표시, 삭제·화면 이동 후 뒤늦은 결과가 복원되지 않는지 확인한다. 입력·순서·보기 전환을 바꿨다면 해당 조작도 확인한다.
- 좁은 모바일과 데스크톱에서 렌더링을 확인한다. 320·390·1440px을 출발점으로 사용하되 변경한 breakpoint에 맞춘다. 페이지 전체의 가로 넘침과 비교표 내부의 의도된 스크롤을 구분하고 장비 상세·카드 전환처럼 펼친 상태도 살핀다.
- DOM의 성공 문구뿐 아니라 스크린샷과 콘솔을 확인한다. HMR로 입력이나 결과가 초기화되면 필요한 상태를 다시 만들고, 마지막 코드 수정 이후의 화면을 검증한다.

필요한 정상 사례가 기록에 없으면 허용 목록과 recorder로 보완한다. 실제 기록과 합성 사례로 각각 확인한 범위, 확인하지 못한 범위를 구분해 알린다. 기록 재생은 실시간 Nexon 호출이나 DB·큐 통합 검증을 대신하지 않는다. 기존 테스트 명령과 커밋 기준은 `AGENTS.md`를 따른다.

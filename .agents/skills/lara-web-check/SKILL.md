# Lara 화면 검증

[로컬 개발](../../../docs/operations/local-development.md)의 합성 미리보기 절차를 사용한다. 같은 체크아웃의 기존 Nuxt 서버를 확인해 충돌을 피한다. 서버 코드를 별도로 복제하거나 브라우저 내부 상태에 가짜 결과를 주입하지 않는다.

변경한 기능의 계약을 [문서 안내](../../../docs/README.md)에서 확인한 뒤 해당 흐름만 검증한다. 군장검사는 [기능 문서](../../../docs/specifications/party-inspection.md)의 범위를 따른다.

- `데모라라`와 `데모부분`, 목록에 없는 이름을 함께 조회해 정상 자료·스탯 누락·캐릭터별 오류가 구분되는지 확인한다. 없는 스탯이 0이나 미착용 판정으로 바뀌지 않아야 한다.
- 수집 UI를 바꿨다면 갱신 중 기존 결과 유지, 완료·실패 표시, 삭제·화면 이동 후 뒤늦은 결과가 복원되지 않는지 확인한다. 입력·순서·보기 전환을 바꿨다면 해당 조작도 확인한다.
- 좁은 모바일과 데스크톱에서 렌더링을 확인한다. 320·390·1440px을 출발점으로 사용하되 변경한 breakpoint에 맞춘다. 페이지 전체의 가로 넘침과 비교표 내부의 의도된 스크롤을 구분하고 장비 상세·카드 전환처럼 펼친 상태도 살핀다.
- DOM의 성공 문구뿐 아니라 스크린샷과 콘솔을 확인한다. HMR로 입력이나 결과가 초기화되면 필요한 상태를 다시 만들고, 마지막 코드 수정 이후의 화면을 검증한다.

미리보기는 일부 section과 대체 이미지만 제공한다. 변경한 영역이 합성 자료에 없다면 관련 테스트·fixture를 사용하거나 자료를 보완하고, 확인하지 못한 범위를 알린다. 기존 테스트 명령과 커밋 기준은 `AGENTS.md`를 따른다.
